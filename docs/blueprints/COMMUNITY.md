# A community people want to join

Blueprint, October 2026. Status: **proposed.** Nothing here is implemented
beyond the repository that already exists (see
[`../PROJECT_PLAN.md`](../PROJECT_PLAN.md) and `CONTRIBUTING.md`). It touches
every roadmap stage, because it is the rails the others run on.

## The promise

Documentation people can actually follow, in more than one language. A place
to ask without being mocked. A roadmap people can help steer. Contributors
treated as the reason the project moves.

## How it works

- **Documentation first.** The repository's docs are the product's manual; this
  blueprint adds translation structure: short sentences, no idioms, consistent
  terms, so translation is mechanical. Translations are tracked per file and
  carry a visible "translated by the community, reviewed by ..." badge —
  unreviewed translations say they are unreviewed, and machine translation
  without a human is labeled as exactly that, never passed off as
  authoritative.
- **A place to ask.** GitHub Discussions (the platform the repository already
  lives on), with pinned "how to ask" guidance and the moderation policy in
  `CONTRIBUTING.md` — plus a conduct policy the project adopts *before* it has
  a community, not after it needs one.
- **A roadmap people can help steer.** Roadmap items link to discussions where
  votes and arguments stay visible; the maintainer records the decision and
  the reason in the item — including "not now, because ...". Nobody's input
  disappears without a written reason.
- **Contributors.** `CONTRIBUTING.md` already exists; this adds the welcoming
  machinery: good-first-issue labels, small scoped work, review within days,
  credit in release notes, and the AI-contribution disclosure rule (Stage 7) —
  contributors must understand, review and test what they submit.

## Honest boundaries

- A community cannot be designed into existence from a blueprint; this
  document builds rails, and the rails are judged by whether people arrive and
  stay. No claimed community size, ever — that number is people, not a metric.
- Translations are real work with real review needs; a language appears when a
  reviewer exists for the level of review being claimed.
- Roadmap votes inform; the maintainer decides, with written reasons. That is
  a different thing from "the community decides", and the difference is stated
  where the votes happen.

## How this gets proven

- Structural: discussions, issue templates, labels, the conduct policy and
  translation badges exist in the repository and are linked from the front
  page — each checkable in CI or by a visit.
- Honest: the first community contributions (issues, translations, fixes) are
  named in release notes with consent; there is no other metric to game.
